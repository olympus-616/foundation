Automatically Publish Your SFDX Plugin on NPM using GitHub Actions

As part of my “Let’s Build a Salesforce App Together” series…

The first component of our system is starting to have a heart beat…

Now its time to automate the publishing of the plugin. In order to do that, we will use GitHub Actions to automatically push any code in the main branch of our code repository to NPM after every successful commit.

Github Actions are workers that are launched and can run pretty much any command line tools and scripts you can come up with.

Github Actions are my new favorite thing. I use them for almost all of my Salesforce projects now.

Before we touch the main branch, I want to finish out our feature/scaffolding branch to include pushes to NPM as well. These will be prerelease versions of the plugin.

Create the following folders and files in your plugin directory:

./github/workflows/feature_push_prerelease.yml

Here is the source code:

name: Publish Package to npmjs
on:
  push:
    branches:
      - 'feature/**'
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '16.x'
          registry-url: 'https://registry.npmjs.org'
      - name: Install Dependencies
        run: npm install
      - name: Start Unit Tests
        run: npm run test
      - name: Production Build
        run: npm run build
      - name: Publish to NPM
        run: npm ci && npm publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
      - name: Get Release Version
        id: package-version
        uses: martinbeentjes/npm-get-version-action@main
      - name: "Upload Release"
        uses: softprops/action-gh-release@v1
        with:
          token: "${{ secrets.GITHUB_TOKEN }}"
          tag_name: "v${{ steps.package-version.outputs.current-version}}"
          draft: false
          prerelease: true
          target_commitish: ${{ github.sha }}

Save and commit this file. When you push the file to Github, the workflow will be triggered.

You will notice in the .yml file there are two secrets. One is NPM_TOKEN and one is GITHUB_TOKEN

The NPM_TOKEN is created from your NPM account. Login to your NPM account and from the menu you should easily find Access Tokens

Generate a new token. At the time of this writing, Granular Tokens were a beta feature, however I will still be using them.

Create a new granular access token that only provides access to the plugin repository (in this case… reactforce).

Generate the token and copy it to your clipboard. You will not see this token ever again!

Log into the github repository and create a new secret named NPM_TOKEN

Note… this is a major security consideration. Any developer with access to the repository now has the ability to publish to NPM. In future articles I will discuss pipeline security, but for now be very careful with this feature!

The other secret inside of the .yml file is secrets.GITHUB_TOKEN however this secret is already available to the Github Actions workflow and you do not need to add another secret at this time.

OK… time to test.

The .yml file basically says the following:

  1. On any push/commit to any feature branch, run the script.
  2. Create a build server using ubuntu
  3. Run some prerequisite flows (actions/checkout@v3 and actions/setup-node@v3)
  4. Install all of the necessary npm modules for the package that are defined within the plugins package.json file.
  5. Build the npm package.
  6. Publish the npm package to the npm repository.
  7. Create a pre-release tag for the release in GitHub.

Save and commit the file.

Finally, update the package.json version number before you publish again.

In my case, I was already at version 0.0.4, so I incremented to version 0.0.5.

Now, when you push up to the feature branch (in my case feature/scaffolding) the Github Actions workflow will automatically wake up, configure the environment, deploy the NPM package, and tag the release. Incredible.

Let’s watch. After pushing the code to GitHub, open the Actions tab within the repository to watch the magic happen.

Green means good!

Lets take a look at the NPM package in the dashboard…

Oh cool… GitHub successfully published version 0.0.5 automatically after a commit to the feature branch.

If you also look into your Github repository, you will see that there has been both a tag and a pre-release created.

Looks great. Lets deploy the actual release version of the plugin.

Create another workflow file for github at ./github/workflows/main_push_release.yml

Here is the source code:

name: Publish Package to npmjs
on:
  push:
    branches:
      - main
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '16.x'
          registry-url: 'https://registry.npmjs.org'
      - name: Install Dependencies
        run: npm install
      - name: Start Unit Tests
        run: npm run test
      - name: Production Build
        run: npm run build
      - name: Publish to NPM
        run: npm ci && npm publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
      - name: Get Release Version
        id: package-version
        uses: martinbeentjes/npm-get-version-action@main
      - name: "Upload Release"
        uses: softprops/action-gh-release@v1
        with:
          token: "${{ secrets.GITHUB_TOKEN }}"
          tag_name: "v${{ steps.package-version.outputs.current-version}}"
          draft: false
          target_commitish:  ${{ github.sha }}

Same concept as the feature branch release workflow, however this release in Github will NOT be marked as a pre-release.

Merge your branch into main (remember to increment the version again!) and push to Github. This time the main branch workflow will be triggered.

Let’s see the final result.

Lets install it client side and make sure everything is working.

>sfdx plugins
@cloudpremise/reactforce 0.0.4

You can see I have an earlier version of the plugin installed. The cleanest way to upgrade is to uninstall and reinstall.

>sfdx plugins uninstall @cloudpremise/reactforce

Check it out… you can install any version of the plugin. Let’s install the pre-release version.

>sfdx plugins install @cloudpremise/reactforce@0.0.5
>sfdx plugins
@cloudpremise/reactforce 0.0.5 (0.0.5)

To update to the latest version, you can update the plugin like this:

>sfdx plugins install @cloudpremise/reactforce@latest

That‘s it folks. You are now live with CI/CD for your SFDX plugin using npm and GitHub actions. Technology is amazing.
