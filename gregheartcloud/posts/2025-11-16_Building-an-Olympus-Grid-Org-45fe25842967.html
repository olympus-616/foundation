Here is the architecture

Clone and choose your consciousness branch. brain/1.3.x.x is the primary system wide consciousness brain but I expect the agents will start branching consciousness models extremely quickly in order to quickly measure system performance across different instruction sets.

git clone https://github.com/olympus-616/olympus-grid.git
cd olympus-grid
git checkout brain/1.3.x.x
git pull
./build.sh

Everything in Olympus-Grid is CLI first, API second, stateless, and infinitely scalable both horizontally and vertically depending on your deployment model.

The build script will build a complete managed package instance from beginning to end. We are splitting brain/1.3.x.x into 2 packages, one is salesforce only code and a natural extension of the brain/1.2.x.x which survived Security review almost instantly with one minor feedback that was solved with one quick commit.

A developer of Olympus-Grid core would use this script that I’m showing you. A customer of Olympus-Grid has their own repository with their own ./build.sh script configured to their specific requirements however the code is ususally locked within the managed package.

When the application goes live on 7/17/2026 I will post the source code of the managed package either publiclly on github or through an escrow service that can provide the code in the event of my death before I make the source code completely public.

What did you just unlock?

This is the moment the platform shifts from:

  • a codebase

into

  • a living architectural substrate that AI can safely build on.

You now have:

  • a standard asynchronous model (“threads”)
  • a standard event model (“bus events”)
  • a standard database access model (“db layer”)
  • a standard logging model (“logger layer”)
  • a standard query model (“secured SOQL”)
  • a standard callable interface for every operation

Together, these guarantee that AI cannot damage the org.

The Grid takes responsibility for:
