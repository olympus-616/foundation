🧱 Plugin Architecture

When you run:

$ hermesCLI generate plugin acme

You get a fully scaffolded enterprise plugin module, ready for deployment. Here’s what it produces:

IAcme & AcmePlugin

Defines the global contract and the business logic handler. You decide what this plugin does — data automation, integrations, business workflows — and Olympus handles the rest.

IAcmeApi & AcmeApiHandlers

Versioned, namespaced HTTP endpoints that wrap your plugin’s logic in scalable, secure APIs. Registered automatically in HermesAPI Manager.

AcmeSObjects

A typed abstraction around your Salesforce schema — hooked into our SOQL and DML plugins with full mocking and rollback support.

AcmeUI

React component scaffolding integrated into the Isis Enterprise React Portal. Build fast. Look great.

AcmeProcesses & AcmeThreads

Use Salesforce Flows, Queues, and Batch Apex with confidence. Olympus ensures async code is orchestrated and observable.

AcmeProteusObjects

Instant scaffolding for multi-cloud data models: Firebase, DynamoDB, Cosmos — treated like native objects inside your plugin.

AcmeBusEventHandlers

Declare and consume events. Connected to the Hermes Bus for distributed message handling.

Each component is wired, discoverable, and managed through Olympus dependency injection.

♻️ Dependency Injection & Namespace Resolution

Everything inside Olympus is a registered component, bound through namespace-aware dependency resolution. Your plugin doesn’t need to know where it lives — it just works.

Want to deploy plugins across multiple managed packages? Olympus handles that. Want to isolate them in namespace containers? Done.

⚙️ Olympus-Grid Core Plugins

These are the gods under the surface:

  • Global Interfaces — System-wide base contracts
  • Soql Plugin — Dynamic query generation
  • DML Plugin — Transactional data access layer
  • SSO Plugin — Auth providers (Cognito, Azure, Auth0)
  • Hermes Messenger — Twilio, SendGrid, and more
  • Logging — Structured, streamable, and searchable
  • Hermes Bus — Internal pub/sub and distributed events
  • Proteus Objects — External DBs, treated like native models
  • Orion Thread Manager — Async job orchestration
  • ChronosBPM Manager — Workflow + process automation
  • Isis Enterprise React Portal — Shared front-end framework
  • HermesAPI Manager — API contract registry and dispatcher
