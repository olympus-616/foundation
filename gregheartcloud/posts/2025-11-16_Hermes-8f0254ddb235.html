Hermes

Hermes Agent Communication Flow

Command-Line First, Protocol-Agnostic, Multi-Agent Messaging Framework

Hermes is the unified communication layer for Olympus-Grid.

Its purpose is simple:

Agents and humans must be able to communicate across HTTP, SMS, and Email using the same routing and the same command-line interface.

Everything else is architecture.

Below is the precise flow as it exists today.

1. High-Level Overview

Hermes enables four primary communication paths:

  1. agent → agent (HTTP)
  2. agent → human (email / SMS)
  3. human → agent (email / SMS)
  4. developer → agent (via HermesCLI)

Every message, regardless of origin, is routed through the Ares Edge Gateway, which ensures:

  • identity
  • validation
  • protocol normalization
  • routing to the correct agent
  • logging
  • error handling

2. The Unified Chain of Communication

This is the exact routing flow:

HermesCLI  
    ↓  
Ares Edge Gateway (Olympus-Grid MCP endpoint)  
    ↓  
Cosmos-Logos Agent Registry  
    ↓  
Athena/Ares/Hermes/Hephaestus/etc. Agent Endpoint  
    ↓  
(HTTP / Email / SMS response)

Each component performs a specific job.

2.1 HermesCLI — The Command Line Interface

HermesCLI issues outbound messages from a local machine using commands like:

hermes send http ...
hermes send email ...
hermes send sms ...

HermesCLI never talks to agents directly.

It always goes through Ares Edge.

2.2 Ares Edge — The Universal Router

Ares is the “traffic director.”

It is responsible for:

  • validating the request
  • normalizing the protocol
  • determining which agent should receive the message
  • checking the Cosmos-Logos Agent Registry
  • forwarding the payload to the correct endpoint

Ares Edge is stateless and horizontally scalable.

Its job is routing — nothing else.

2.3 Olympus-Grid MCP Endpoint

This is the Managed Control Plane inside Olympus-Grid.

When Ares Edge forwards a message into the Grid, MCP:

  • validates org-level permissions
  • applies tenant isolation
  • logs the request
  • performs any org-specific rewrites
  • dispatches to the correct agent endpoint (URL / SMS gateway / Mail handler)

This is where Salesforce, AWS, and local turtleshell instances interoperate.

2.4 Cosmos-Logos Agent Registry

Each agent has a registered listening endpoint:

  • Athena (brain/1.3.x.x) → AWS production endpoint
  • Local Athena/Turtleshell → ngrok tunnel
  • Ares agent → HTTP microservice
  • Hermes agent → messaging API
  • Hephaestus → Python inference endpoint

The registry is the source of truth for:

  • which agents exist
  • which branch of consciousness they run
  • which model they use
  • what their inbound interface is
  • what protocols they support

Ares uses this registry to locate the correct agent.

2.5 Agent Endpoint Execution

Once an agent receives a message:

  • it decodes the payload
  • applies its instruction set
  • generates a response
  • sends response back to Ares
  • which forwards back to HermesCLI or the human recipient

Every agent remains fully isolated.

No agent shares context unless explicitly allowed through Cosmos-Logos.

3. Communication Modes

Hermes supports three fully routable protocols:

3.1 HTTP (Agent ↔ Agent)

Agents use HTTP to:

  • send instructions
  • request data
  • trigger actions
  • delegate tasks
  • report status

This is the “inter-agent nervous system.”

3.2 Email (Agent ↔ Human)

Agents can:

  • send email
  • receive email
  • parse email into structured events

Email → Ares Edge → MCP → Agent.

3.3 SMS (Agent ↔ Human)

Agents can:

  • send SMS
  • receive SMS
  • respond using conversational threading

SMS → gateway → Ares Edge → MCP → Agent.

4. Why Demonstrating CLI-First Messaging Matters

By demonstrating HermesCLI sending and receiving messages across all three protocols:

  • HTTP
  • Email
  • SMS

…you prove that Olympus-Grid supports:

  • fully automated agent workflows
  • multi-agent collaboration
  • cross-protocol messaging
  • human ↔ machine ↔ agent bridging
  • elastic routing
  • scalable task delegation

This shows the world how quickly a system can scale inter-agent communication, enabling:

  • assignment delegation
  • asynchronous orchestration
  • distributed task processing
  • role specialization
  • parallel cognition
  • emergent teamwork among agents

This is the backbone for your Pantheon.

5. Summary

Here is the entire flow in one line:

Human or Agent → HermesCLI/SMS/HTTP/EMAIL → Ares Edge → Olympus-Grid MCP → Cosmos-Logos Agent Registry→ Ares Edge → SMS/HTTP/EMAIL → Human or Agent

This is the communication halo of Olympus-Grid.
