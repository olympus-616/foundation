Publishing a SFDX Plugin to NPM

As part of my “Let’s Build a Salesforce App Together” series…

The next step of the app is to publish the plugin to the NPM repository.

Create an NPM account: https://www.npmjs.com/signup

Update or Install NPM if you haven’t yet.

>npm install npm@latest -g

Update the package.json. For this project I will be following these instructions.

From the main plugin directory (in my case reactforce) run the following command:

>npm init --yes

This will slightly update the existing package.json file.

I also scoped the package to my NPM’s organizational account (CloudPremise)

>npm init --scope=@cloudpremise

In order to publish the package, update the hello command to be your plugin name. I did this by renaming the folders in the src and test folder from hello to reactforce. Also make sure the scope of the package is correctd in reactforce/src/commands/reactforce/org.ts file

#WAS
onst messages = Messages.loadMessages('hello', 'org');

#NOW
const messages = Messages.loadMessages('@cloudpremise/reactforce', 'org');

Login to npm from the command line

>npm login

#Follow the prompts to login to your npm account

Time to publish…

>npm publish --access public

Assuming you are authenticated to the correct npm account (which belongs to your scoped organization..) you will see something like this on the NPM registry:

Cool! The plugin is now loaded into the npm registry and now you can run the following command from your developer workstation:

Install the plugin

>sfdx plugins install @cloudpremise/reactforce@latest

There will be a warning about the fact the plugin is not signed by salesforce. Just accept the warning for now and also you can always setup a plugin whitelist by referring to this article.

Test the plugin!

>sfdx reactforce:org -h

Uninstall the plugin when you are done testing.

>sfdx plugins uninstall @cloudpremise/reactforce
