Authorizing a Salesforce Org using JWT

If you ever needed to connect to a Salesforce org using JWT… 


Windows Instructions

  • Navigate your shell to your ssh folder {{userprofile}}/.ssh

Create a temporary passphrase (e.g. coolbeans)

$ openssl genrsa -des3 -passout pass:coolbeans -out server.pass.key 2048
  • This process creates the server.pass.key file in ~/.ssh/

Create a private key

$ openssl rsa -passin pass:coolbeans -in server.pass.key -out server.key
  • This process creates the server.key file in ~/.ssh/

This is the private key for the server which is similar to a password. Please do NOT commit this to your source control people.

Generate a CSR (Certificate Signing Request)

$ openssl req -new -key server.key -out server.csr
  • Enter the key pass phrase from above (coolbeans!)
  • Enter the CSR Info or press enter for defaults
  • This process creates the server.csr file in ~/.ssh/

Generate the x509 Certificate from the CSR

$ openssl x509 -req -sha256 -days 365 -in server.csr -signkey server.key -out server.crt
  • This process creates the server.crt file in the ~/.ssh/
  • This is the x509 certificate — the “public” key of your private key. This is the file that gets loaded into the digital certificate for the connected application in Salesforce


MacOS Instructions

  • Navigate your shell to your ssh folder {{userprofile}}/.ssh

Create a temporary passphrase (e.g. coolbeans)

$ openssl genpkey -des3 -algorithm RSA -pass pass:coolbeans -out serv.pass.key -pkeyopt rsa_keygen_bits:2048
  • This process creates the server.pass.key file in ~/.ssh/

Create a private key

$ openssl rsa -passin pass:coolbeans -in server.pass.key -out server.key
  • This process creates the server.key file in ~/.ssh/

$ openssl x509 -req -sha256 -days 365 -in server.csr -signkey server.key -out server.crt

Note… sometimes the passcodes that you work WILL FAIL! Don’t ask me why… but I have found that if you are having unexpected errors with the key generation process that you should try a different passcode. At least that worked for me!

Setup the connected app in the Salesforce environment you are logging into with JWT

  • Create a connect app
  • Connect App Name: Coolbeans
  • API Name: Coolbeans
  • Contact Email: andy@hotrod.com
  • Enable OAuth Settings: true
  • Callback URL: http://localhost:1717/OauthRedirect
  • Use Digital Certificates: true
  • Upload server.crt
  • Selected OAuth Scopes
  • Api
  • Refresh_token
  • Save
  • Copy the Consumer Key


  • Grant Access to the Connect App via Permission Sets
  • Change the policy for the connected app to
  • Manage → Edit Policies
  • Admin approved users are pre-authorized
  • Create a new Permission Set
  • Name: Coolbeans

  • Assigned Connected Apps
  • Coolbeans
  • Assign the permission set to your user



  • Test the JWT access to the org from the command line
sfdx force:auth:jwt:grant -clientid {{consumer_key_copied_from_above}}  -username {{salesorce_username}} -jwtkeyfile ~/.ssh/coolbeans.key -setalias coolbeans


For Github Actions:

  • Setup the Github Secret in the repository (encode your ssh key here: https://www.base64encode.org/)
  • SFDX_CLIENT_ID
  • Paste the client id from the connected application
  • SFDX_HUB_KEY
  • Paste the entirety of the private key


For Bitbucket Pipelines:

  • Setup the variables in the repository (encode your ssh key here: https://www.base64encode.org/)
