How to setup URL rewriting on a Reactforce Experience Cloud site


React is a Single Page Application (SPA) which means that after the initial page load, the entire react application lives locally in your browser’s memory. 

A modern site should have a good URL structure within the SPA, and React has the React Routing library to support this type of functionality.

One issue that I’ve had to continually overcome when building serverless applications is how to properly manage the url slugs and the query string parameters.

Because the react application sits at the https://{{salesforce_site_domain}}/{{reactforce_url}}, typically all other slugs within the react application would not be found by the Salesforce platform and end up with a 404 and nasty salesforce screens.

The Problem

How do we get deep linking to work with a reactforce Experience Cloud application?

We also need to be able to preserve any query string paramaters that are passed into the application. This is critical for any kind of marketing attribution associated with traffic to your Experience Cloud site.


The Solution

I’m giving away all the secret sauce on this one. If only those who read this blog could understand the magic of the next few minutes of reading.

  1. Add React Routing /contact /users etc notice that the site blows up when you hit the route
  2. Add the url rewriter class (which is under the site settings which are hard to find)
  3. Add rte and site url to the visualforce page that hosts the react force application.
  4. Allow React to Redirect to the route based upon what is passed into the rte div on the page
  5. Debugging — In order to debug the UrlRewriter Class, set up debugging on the Site’s Guest User from the Setup → Debug Logs.

Lastly, I like to use the default rewriter to keep the Landing page from getting in the way


This solution effectively always redirects anything other than the specific routes identified in the urlwriter back to the react app, but it puts all of the rest of the route including query string params into the visualforce page inside of a div that should be able to be read from react.

React then inspects the rte and can rerender to the “correct” url. Net effect is deep linking now works on your Reactforce Experience Cloud! OMG I just gave away the golden goose. Well… not all of it.
