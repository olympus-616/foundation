SFDX Plugin Pipeline

As part of my “Let’s Build a Salesforce App Together” series…

I am building a Salesforce (SFDX) plugin for assisting developers who desire to use ReactJS as the user interface programming language. Sorry Aura and LWC… the grass is greener on the other side of the fence. And developers are cheaper. (Remind you that I’m a tech founder and even though I’m a certified technical architect, I have a reputation for being the first one to say when NOT to use Salesforce)

I will write all about my plugin in later, but first I want to cover the deployment architecture for the plugin.

The system architecture is shown above.

  1. The plugin will be delivered via NPM to the React/Salesforce developer.
  2. The code for the plugin will automatically be automatically published to the NPM repository upon a successful commit to the main branch.
  3. Pre-release versions of the plugin will also be available for testing.
  4. The documentation for the plugin will be stored on GitBook and automatically kept in sync with the repository. I will use GitBook to generate the markdown files
  5. The product website will be a serverless react application initially hosted on Netlify. Commits to the main branch will push a new build.

Lets see how this all works. First lets create the plugin.
